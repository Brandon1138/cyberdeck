# Resource measurement adapters

These adapters are measurements, never admission or cleanup authority. Composition supplies canonical owners and reconciled process roots or immutable container IDs. Samples retain no argv, environment, command output or exception text.

`MacosProcessSampler` runs one selected-column ps invocation per poll. Memory is RSS, not physical footprint. CPU is ps averaged usage divided by 100 (one logical core = 1). PID plus ps start time fences observed reuse, with **one-second precision**: same-second PID reuse cannot be conclusively distinguished. This identity is unsuitable as termination authority. Only descendants observed while connected to an owned root can survive reparenting; processes born and orphaned between polls are unknown. Missing roots return unknown, not zero. Explicit nested roots partition trees. Process scanning is capped by a 1 MiB output bound.

`ContainerResourceSampler` consumes raw cgroup readings with exact registered IDs and installation identity; foreign records are not charged. Its foreign count covers only the supplied inventory, not global engine discovery. `cgroupV2Reader` is a narrow read-only implementation for **already reconciled** installation-owned immutable container IDs, at most 64 per collection. It executes cat on three fixed cgroup v2 files; it does not independently discover or authenticate ownership labels. Composition must do that reconciliation before passing identities. Unsupported cgroup layouts, missing cat, stopped guests and denied reads yield unknown. CPU is usage_usec delta over monotonic elapsed time; its first sample is unknown. The short exec process contributes overhead. No Docker CLI cache-adjusted memory is mislabeled as memory.current. Each command has a two-second kill timeout and 1 MiB buffer cap; 64 sequential reads can therefore take up to roughly 128 seconds. Prefer smaller batches and report sample age; the aggregate rejects samples older than 15 seconds.

`ResourceSampler` coalesces overlapping collections and keeps at most 120 snapshots by default (configurable 1–3600). Sources must finish in bounded time; production command adapters enforce that bound. At most 512 validated samples are accepted per source, with stale or wrong-source samples rejecting that source. A failed source is unknown. Host RSS, guest cgroup usage and shared VM measurements remain separate. There is deliberately no computed installation physical total: RSS overlap and attributable shared-VM overhead require physical accounting before admission can trust such a total. Shared VM discovery/calibration is not implemented here. No calibrated runnable envelope is provided.

Deterministic tests exercise two trees, reparenting, PID reuse, nested ownership, denied metrics, foreign containers, interval CPU, coalescing and bounded retention. They do not establish live footprint accuracy, sampler overhead, end-to-end broker ownership, native service attribution, engine label reconciliation, or MacBook acceptance.

## Native macOS collector

`infra/resources/process-sample.c` builds with `xcrun clang -O2 -Wall -Wextra -Werror infra/resources/process-sample.c -o /absolute/helper/path`. It is an optional, explicitly injected absolute executable for `NativeMacosProcessSampler`; composition owns installation and selection. No runtime compiler, elevated helper, argv read or environment read is introduced. This branch does not change broker composition or package/install behavior.

One invocation enumerates up to 16,383 PIDs and emits a numeric versioned table. `PROC_PIDTBSDINFO` supplies birth seconds plus microseconds, checked before and after `proc_pid_rusage` to discard reuse/exit races. `RUSAGE_INFO_V2` supplies `ri_phys_footprint`, resident size and cumulative user/system nanoseconds. A monotonic timestamp accompanies each row. CPU fraction uses per-identity deltas between successful observations; the first observation, reset or denied counter is unknown. Denied rusage preserves the identity with unknown memory. Missing BSD rows increment an inaccessible count and produce `process-table-incomplete`. This uncertainty includes permission denials and exit races; it does not prove an inaccessible process belongs to Cyberdeck.

The parser requires a complete trailer and rejects invalid numbers, duplicate PIDs, excessive output and malformed birth times. Root identity must come from the same native format (`libproc:<seconds>.<six microsecond digits>`); no ps-to-native identity conversion is guessed. `readTable()` exposes identity capture, coalesces simultaneous reads, and returns independent copies. It has no settled-result cache. Ownership still cannot discover a process born and orphaned entirely between polls, and a scan is not a simultaneous kernel snapshot. A parent born after a child is not used as ownership evidence. Birth identity improves attribution but is not, alone, process termination authority: a future termination path must revalidate immediately before signaling.

Physical footprint remains separate from RSS in `ResourceSnapshot.managedHostPhysicalBytes`; a mixed-kind host collection has neither total. A physical sum measures attributed native processes and does not solve shared-VM attribution or establish whole-installation memory. The RSS fallback explicitly carries `not-reclamation-identity`. Bounded retention and stale-source checks still apply. The low-rate poller must not convert old cached health into fresh observations.

## Host collector comparison (2026-09-16)

`resource-native-benchmark.json` contains sanitized aggregates from three warm-up pairs and 20 alternating native/ps pairs on macOS 27 arm64. Native median wall time was **22.25 ms**, versus **90.92 ms** for ps; median child CPU was **10.04 ms**, versus **42.89 ms**. Native self physical footprint was **1.27 MiB** and self RSS **1.70 MiB**. At one poll per five seconds, median collector child CPU alone extrapolates to roughly 0.20% versus 0.86% of one core; this is an estimate, not an observed settled CPU window.

Coverage differs: native emitted a median 604 rows with 303 inaccessible processes; ps returned 907 rows. Therefore the speed comparison does not imply equal global coverage. Host load was uncontrolled, the Python driver is excluded from child CPU, and wall p95 was 74.78 ms native / 162.32 ms ps. The tool keeps raw rows only in memory, saves no PIDs or process identities, and bounds each subprocess to two seconds / 1 MiB. Reproduce with `python3 infra/resources/benchmark-process-sample.py /absolute/helper/path /absolute/summary.json`. No provider or container launch, broker restart, cleanup action or VM attribution was performed. This short comparison is not W0/W1 acceptance or runnable-profile calibration.
