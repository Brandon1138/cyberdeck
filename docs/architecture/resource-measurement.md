# Resource measurement adapters

These adapters are measurements, never admission or cleanup authority. Composition supplies canonical owners and reconciled process roots or immutable container IDs. Samples retain no argv, environment, command output or exception text.

`MacosProcessSampler` runs one selected-column ps invocation per poll. Memory is RSS, not physical footprint. CPU is ps averaged usage divided by 100 (one logical core = 1). PID plus ps start time fences observed reuse, with **one-second precision**: same-second PID reuse cannot be conclusively distinguished. This identity is unsuitable as termination authority. Only descendants observed while connected to an owned root can survive reparenting; processes born and orphaned between polls are unknown. Missing roots return unknown, not zero. Explicit nested roots partition trees. Process scanning is capped by a 1 MiB output bound.

`ContainerResourceSampler` consumes raw cgroup readings with exact registered IDs and installation identity; foreign records are not charged. Its foreign count covers only the supplied inventory, not global engine discovery. `cgroupV2Reader` is a narrow read-only implementation for **already reconciled** installation-owned immutable container IDs, at most 64 per collection. It executes cat on three fixed cgroup v2 files; it does not independently discover or authenticate ownership labels. Composition must do that reconciliation before passing identities. Unsupported cgroup layouts, missing cat, stopped guests and denied reads yield unknown. CPU is usage_usec delta over monotonic elapsed time; its first sample is unknown. The short exec process contributes overhead. No Docker CLI cache-adjusted memory is mislabeled as memory.current. Each command has a two-second kill timeout and 1 MiB buffer cap; 64 sequential reads can therefore take up to roughly 128 seconds. Prefer smaller batches and report sample age; the aggregate rejects samples older than 15 seconds.

`ResourceSampler` coalesces overlapping collections and keeps at most 120 snapshots by default (configurable 1–3600). Sources must finish in bounded time; production command adapters enforce that bound. At most 512 validated samples are accepted per source, with stale or wrong-source samples rejecting that source. A failed source is unknown. Host RSS, guest cgroup usage and shared VM measurements remain separate. There is deliberately no computed installation physical total: RSS overlap and attributable shared-VM overhead require physical accounting before admission can trust such a total. Shared VM discovery/calibration is not implemented here. No calibrated runnable envelope is provided.

Deterministic tests exercise two trees, reparenting, PID reuse, nested ownership, denied metrics, foreign containers, interval CPU, coalescing and bounded retention. They do not establish live footprint accuracy, sampler overhead, end-to-end broker ownership, native service attribution, engine label reconciliation, or MacBook acceptance.
