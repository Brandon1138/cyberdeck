# W1 collector status

`scripts/prove-resource-fleet.ts` is a fail-closed, read-only preflight, not live W1 acceptance. It never starts providers, containers, a broker, or an Orc. Task G remains incomplete. The evidence validator checks consistency and hashes; neither it nor this preflight authenticates runtime evidence.

Run with Node 24 using `node --import tsx scripts/prove-resource-fleet.ts <private-config.json> /private/tmp/cyberdeck-resource-NEW`. Output must be new; the directory is created mode 0700 and its report mode 0600. Exit status is always nonzero while live collection is blocked. No default broker or credentials are discovered. A config must explicitly supply the strict `CollectorConfigSchema`: clean candidate source SHA, config/profile SHA256 hashes, image digest; broker and installation UUIDs; isolated `/private/tmp/cd-resource-NAME.sock`; absolute config/profile file paths; eight subscription worker selections covering both Claude and Codex (provider/model/effort/authMode); subscription first-party Codex orchestrator selection; bounded timeout and sampling interval. No timestamps or externally supplied events are accepted.

The command verifies local source/config/profile pins before connecting to the explicit owned nonsymlink Unix socket. It reads only resource, execution, evaluation and activity health, and retains only presence/configured/degraded flags. Requested broker identity and image/config/profile pins cannot currently be attested through these health responses; they are explicitly unverified. Health payloads are not copied because they can include private paths. Input files must be absolute, owned regular files with no group/other permissions. Descriptor reads reject final symlinks and nonregular files, cap the collector config at 64 KiB and pin files at 1 MiB, and reject changes during reading. Failed inputs produce a sanitized nonzero result; after output creation a failure stage/reason is retained in `failure.json` (or a separate durable-write failure is reported). A created output directory is never overwritten or deleted.

## Missing production contract

Live collection requires an authenticated isolated-broker identity/pin handshake, narrow shared-admission worker dispatch, a real eight-provider barrier driven by native ready/progress events, first-party Codex Orc lifetime accounting, bounded attributed samples including sampler cost, per-attempt evaluation dispositions, and complete scoped teardown with ownership proof. Unknown authentication, capture, output or ownership must remain unverified. The current command deliberately does not invent these RPCs or use host/engine fallback.

`collectSequence` is an internal adapter seam exercised only by deterministic tests. It journals intent before each bounded attempt, runs one warmup followed by three measured eight-worker attempts sequentially, retains failed runs, requests scoped cleanup after every attempt, and stops if cleanup is unknown or a timed-out launch operation remains unsettled, even when cleanup reports success. The adapter must fence late launches on abort and make cleanup wait for launch quiescence; a promise timeout alone does not prove cancellation. No adapter can be loaded through CLI configuration. It does not claim progress, overlap, sample completeness or acceptance from adapter results. Wiring a production adapter and collecting real evidence remain required work, including the 8 GiB sample gates and disposition reconciliation.

No live broker/provider/OrbStack/Docker was used to test this implementation. Preserve private output locally under the operator's retention policy; publish only reviewed sanitized summaries.
